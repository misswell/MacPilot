# Awake P0 手工验收

这些场景依赖真实的 macOS 电源与显示器状态，不能完全由 Swift Testing 自动化。

1. 在菜单栏选择「保持唤醒」后运行 `pmset -g assertions`，确认出现 `PreventUserIdleSystemSleep`；重复点击不会产生额外 assertion。
2. 保持「允许显示器休眠」开启，等待系统显示器休眠超时：显示器可以关闭，但系统不会因 idle 进入 system sleep。
   - 会话运行时再点击「关闭屏幕」：不得出现独立的 `MacPilot screen off` / `PreventUserIdleDisplaySleep` 断言；熄屏不能覆盖 Awake 的允许休眠策略。保持键鼠无输入，按系统空闲时间进入显示器休眠，并遵守系统的锁屏设置。
   - 打开「阻止显示器休眠」后重复：防休眠断言只能由 `MacPilot Awake` 持有；停止会话后应释放，即使仍处于熄屏状态。
   - 核对 `DisplayPower` 日志中的每屏回读：`ddcOffSent` 不代表已关屏，只有 `ddcOffConfirmed` 才表示显示器确认电源状态。背光仍非零、DDC 未确认时必须进入黑色覆盖降级；部分屏幕无法覆盖时返回失败并恢复已经改变的屏幕。
3. 选择自定义时长 1 分钟，确认约 60 秒后菜单栏恢复非 Awake 状态，`pmset -g assertions` 中的 Awake assertion 消失。
4. 在 Awake 设置中选择「直到指定时间」，设置一个临近时间，确认到点后 Session 和 assertion 都结束；手动修改系统时间后重新打开设置也应立即刷新。
5. Session 运行期间让 Mac 睡眠再唤醒；唤醒后若 Session 已到期，应立即结束，否则 assertion 继续按当前 Session 聚合状态保持。
6. 在电池电量低于阈值的 Mac 上开启电量保护，确认所有 Awake Session 自动结束；关闭保护后不应自动恢复已经结束的 Session。

退出 MacPilot 后再次运行，确认上一次手动 Awake Session 不会恢复；这是 P0 的默认启动策略。

## Awake P1 自动规则

7. 在 Awake 设置的「自动规则」中新增 Process Running 规则，填写 `claude`，保持「阻止系统休眠」开启。启动并退出 Claude CLI，确认规则分别创建和结束 Trigger Session；重复进程事件不应创建多个 Session。
8. 新增 Application Running 或 Application Frontmost 规则，填写目标应用的 Bundle ID。启动或切换到该应用后，确认规则状态和 Session 详情显示自动规则来源。
9. 新增 Power Adapter Connected 规则。插入和拔出电源适配器，确认对应 Trigger Session 随电源状态开始和结束。
10. 新增 External Display 规则并设为至少 1 台。插拔外接显示器，确认 Session 随显示器重配置事件开始和结束。
11. 为任一规则设置启动/停止延迟：状态短暂变化不应闪断 Session；持续超过延迟后才应切换状态。
12. 停用或删除最后一个使用 Process、Power 或 Display 的规则，确认对应 Monitor 停止；没有相关规则时不应持续轮询这些系统状态。

## 断言健康与菜单栏状态

13. 启动无限期会话，用 `pmset -g assertions` 记录 MacPilot 的断言 ID；等待至少 65 秒再检查，健康断言应保持原 ID，不重复创建。
14. 启动「当显示器关闭时允许系统睡眠」会话，关闭显示器再唤醒。显示器关闭期间会话仍在运行，但菜单栏不应把已释放的断言标为「已阻止」；唤醒后断言恢复。
15. 菜单栏同时显示系统与显示器的断言状态；对照 `pmset -g assertions` 检查。打开「阻止显示器休眠」时两者均应为「已阻止」。
16. 创建、健康查询或释放失败时，菜单栏显示异常图标与错误；会话结束后的释放失败仍会重试，成功后停止维护任务。故障注入由 `AwakeAssertionControllerTests` 自动覆盖，不能用杀死系统 powerd 的方式验收。

自动化测试不会替代真实设备的显示器、睡眠、合盖和电量验收；发布前记录哪些场景已手工验证。

## BLE 监控与闲置熄屏

- 关闭「靠近时唤醒」，保持原来的主动监控设置，手机留在电脑旁。停止键鼠操作后，约 30 秒内应转为仅广播扫描；日志应记录主动连接暂停，不能继续每分钟重连手机并刷新 `Bluetooth LE HID Activity`。不要为了验收修改系统熄屏时间。
- 等待系统原定的显示器休眠时间，确认屏幕可以关闭；再用键鼠正常操作，确认主动监控恢复且用户的主动/被动模式设置未被改写。
- 空位移的合成鼠标事件、BLE 广播和连接回调不得重置输入闲置窗口。开启「靠近时唤醒」后，原有靠近唤醒行为仍可用。
- 此处是验收步骤，不代表已经完成长时间真机验证；运行中的本机应用不随发布自动替换。

## 合盖运行设置与恢复

17. 开启「合盖后继续运行」并开始会话：未授权时页面提供允许后台服务或打开系统设置的按钮；授权后返回 MacPilot，无需重启或终端操作即可继续启用。服务就绪但没有运行会话时，应提示开始会话后才生效。
18. 等待页面显示「已生效」后，分别在电池和接电源状态下合盖运行后台任务。测试人员可用 `pmset -g` 核对 `SleepDisabled` 为 1；用户无需输入命令。系统读取失败或开启失败时，页面及会话详情不得显示合盖休眠「已阻止」，并提供「重新检查并修复」。
19. 测试人员在会话运行中将系统防休眠值重置为 0：返回设置页应立即检查并恢复；不打开设置页时应由下一次心跳检查恢复（默认间隔 30 秒）。连接健康、后台服务仍记录所有权也必须恢复，不能把它们当成系统设置已生效的证明。升级后旧版后台进程仍在运行时，也应能清理过期所有权并恢复设置，无需重启服务或 Mac。
20. 会话停止或低电量保护结束会话后，不应自动恢复合盖防休眠。睡眠后唤醒仍有合盖会话时，应重新检查实际系统状态。

## 熄屏实机验收记录（2026-10-08）

`MACPILOT_TEST_DISPLAY_BLANK=1 swift test --filter DisplayBlankHardwareTests` 会短暂熄灭已连接的屏幕并恢复，只在显式开启时运行。已有熄屏恢复快照时拒绝运行，避免覆盖正在运行的应用状态。

- 本机内置屏：熄屏后背光回读为 `0`，恢复后为原值 `0.7199811`。
- 本机外接屏：熄屏后 DDC 电源模式回读为 `4`，恢复后为 `1`。
- 测试先创建并释放一条探针断言以核对查询有效；实际熄屏阶段没有创建 `PreventUserIdleDisplaySleep` 断言。
- 已验证短时熄屏、断言和恢复。系统空闲 10 分钟后的自动休眠、合盖和整夜状态仍按上述手工场景验收；本次没有修改系统休眠时间或替换本机安装。
