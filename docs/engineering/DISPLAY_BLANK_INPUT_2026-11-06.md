## 修改前协议七问

1. **可确认的代码缺陷：** `DisplayPower` 只比较 ANY 事件计数，无法区分用户输入、
   无位移指针事件、系统事件或计数重置。此次事件的具体来源仍未记录。
2. **历史与规则：** `disp-001-recovery-not-durable`、`ble-003-background-session-misjudge`；
   `bcd48c5` 规定黑屏不阻止系统正常空闲熄屏，`037040a` 规定 BLE 重连不得唤醒屏幕。
   BLE 的 genuine-input 分类也已有 no-op pointer 与自动解锁事件回归。
3. **旧修复不足：** ANY 计数解决了轮询之间漏掉输入的问题，但把计数变化误当成输入意图。
   修复需要保留输入可检测性，同时验证明确的输入种类和实际位移，并记录解除原因。
4. **受影响功能：** 手机/菜单黑屏后的本地输入解除、系统正常熄屏/唤醒、
   显式手机亮屏、崩溃恢复和 BLE 对 held-blank 状态的响应。保持 journal 与权限边界不变。
5. **必跑测试：** 当前选择器命中的显示恢复与 BLE 历史套件；当前工作区原有修改仍使计划
   升级为完整安全集合，显式串行执行同一集合，不缩小过滤范围、不增加豁免。
6. **新增回归：** 系统计数变化不亮屏、静止指针不亮屏、有效键鼠仍解除、计数重置不亮屏、
   计数环绕仍能识别真实增长，以及忽略事件后的重新取基线/生命周期行为。
   测试只注入数据和效果，不发送真实输入、不操作真实屏幕。
7. **人工验收：** 手机黑屏后跨过系统调光/熄屏周期、真实键鼠唤回、手机显式亮屏、
   内屏与 DDC 外屏、BLE 重连仍需隔离环境验证。当前用户会话不进行这些操作。
