# 看图：生命周期与回归

## 变更前影响分析

1. 根因与目标：MacPilot 没有文档查看器；独立看图应用的进程级缓存不能直接搬进常驻工具箱。
2. 历史规则：`win-001-main-window-opener`、`win-002-login-startup-readiness`、`cfg-001-downgrade-wipe`、`upd-001-designated-requirement`。
3. 旧修复边界：保留晚启动、设置窗口抬升和签名流程。文件路由单独缓冲到配置就绪；看图新增启用列表值，不新增或收紧配置键。
4. 影响面：首页和侧栏、应用菜单和状态菜单、Finder/LaunchServices 冷热打开、配置、退出和打包。截图 URL scheme 仍走原通道。
5. 验证：索引增补触发完整安全套件；重点检查启动、配置、菜单、截图、签名及全部看图套件。
6. 新增测试：资源分层和关闭竞态、解码与预算、文件夹订阅、窗口状态、打开路由、配置默认值。
7. 实机：已安装版本升级降级、从 Finder 冷热打开、混合 DPI/全屏/打印和 Instruments 资源验收，都不能由自动化替代。

## 不变量

- 关闭只存在轻量代理；开启只创建 Runtime；显式打开文件或文件夹才建立资源会话。空文件夹结果不留下会话。
- 最后一个窗口关闭或功能关闭须撤销队列、索引订阅、动画帧、压力监听和缓存。过期结果不得更新窗口或重新建立会话。
- 文件夹索引不递归；同目录索引在活动订阅间共享，撤销最后一个订阅即取消。解码能力以 ImageIO/PDF 实际结果为准。
- Finder 文件不作为深链广播，不修改默认应用；显式打开图片是临时使用授权，不修改首页开关。窗口命令不使用全局按键监听。
- 画布直接接收解码帧及变换变化。SwiftUI 可能复用相同 AppKit 画布，不能依赖 SwiftUI 更新时顺带重绘。

## Finder 直接打开（img-003）

1. 根因：文件路由原先把关闭状态变成「抬首页」；SwiftUI 冷启动自动抬设置窗口；扩展把任意目标标成目录，并逐个调用 LaunchServices。
2. 历史：`img-001` 所有权、`img-002` 启动缓冲、`win-001`/`win-002`（`9d71f61` 曾回退错误的窗口保活修复）。
3. 旧实现的默认关闭正确，但把显式外部打开和持续启用混为一谈；本次不改变持久化意图，保留原启动缓冲和设置窗口创建者。
4. 影响面：应用激活、Finder 批量选择、看图诊断及设置入口；不改 FinderSync 注册、鉴权、深链、系统文件关联或其他功能。
5. 验证：看图路由/生命周期、AppLifecycle、MainWindowOpener、配置、Finder 扩展文件 URL，并运行安全回归选择器。
6. 新增测试：冷启动缓冲、多选、普通目录、临时/常驻与运行中切换、空闲回收、原有设置窗口入口。
7. 实机验收：退出后及运行中分别使用 Finder 系统菜单和扩展菜单测试 JPG、PNG、HEIC、WebP 与五张图片；验证不抢设置、不重复启动、不改开关。

## 看图冷启动不显示设置（img-004）

1. 根因：`d73aafe` 只在 bootstrap 快照中检查有没有待处理文档，并在第一次 orderOut 后撤销窗口抑制；晚到的文档事件、重新激活或恢复窗口仍可能让设置出现。
2. 历史：`img-003`、`win-001`、`win-002`；继续遵守设置 opener 的保留和下一事件循环抬窗规则。
3. 旧实现靠短时隐藏；新实现从启动就等待肯定的设置打开意图，文档打开不授权显示设置。
4. 影响面：SwiftUI 初始设置窗口、AppKit 普通启动和重新打开回调、显式设置深链；不改看图会话、Finder 关联、开关或启动服务。
5. 验证：看图路由、启动生命周期、设置 opener、AppPresence、截图和安全回归。
6. 自动化覆盖文档先到与后到、暂存队列排空后、隐式设置窗口重新排序，以及显式设置仍能创建窗口。
7. 隔离桌面实测 Finder 打开、普通 Finder/Dock 启动和菜单设置，自动化不能替代真实 WindowServer 排序验收。

关闭设置窗口后撤销本次显示许可，系统再次激活该窗口时继续抑制。Dock 状态按 opener 所持窗口的身份更新。图片打开期间已显示的设置窗口保留原状态。正常打开设置仍通过既有 opener。`MainWindowOpenerTests` 和 `ImageViewerWindowTests` 分别钉住窗口与画布回归。

## 看图格式关联（img-005）

1. 原需求只提供 Finder 临时打开；新版移除最近打开状态，提供单格式的系统默认应用管理。
2. 历史：`img-002`、`img-003`、`cfg-001-downgrade-wipe`；Alternate 声明与默认处理器是不同概念。
3. 不把「支持打开」误当作「默认打开」，不修改宽泛的 `public.image` 或 `public.data`。只在明确选择应用时通过 macOS API 修改一个具体内容类型，由系统在需要时取得同意。
4. 关联由系统持有，不进入 MacPilot 配置、Feature 开关或 Runtime；页面只读当前默认及兼容应用，从设置页可切换回其他应用。
5. 验证关联模型、配置、原 Finder 路由、运行时和全量安全门禁。
6. 测试使用替身，不修改真实关联；覆盖只读刷新、单格式写入、取消、重入、成功后回读与未生效提示。
7. 授权后在隔离桌面验证系统确认、双击打开和切换回原应用；不得在用户当前账户自动改变默认应用。

## 滚轮翻页与缩放（img-006）

1. 需求：上一张/下一张不再只靠按钮和方向键；用户可选择滚轮或 `Option+滚轮` 翻页，另一个手势负责放大缩小。
2. 历史：`img-001` 窗口/会话所有权、`img-003` Finder 直接打开；滚轮此前固定缩放，未区分修饰键。
3. 旧行为只有一条缩放路径；新模式必须保证同一事件只做一件事，不能既翻页又缩放。
4. 影响面：看图窗口的滚轮事件、设置页、配置持久化和运行时设置传播；不改变按钮、方向键、pinch、菜单命令或图片解码。
5. 验证：手势纯逻辑、配置契约、运行时传播、注册回归选择器和安全全量门禁。
6. 自动化覆盖两种模式、Option 中途切换、触控板单步、惯性忽略、短手势阈值、鼠标连续快速滚动逐事件翻页、零 delta `.ended` 重置和缩放曲线。冷却期内丢步曾使一次猛滚只切一张，鼠标非精确事件不得再按时间合并。
7. 隔离桌面分别用鼠标滚轮与触控板验证两种模式、首尾边界、缩放锚点、重启保留和多窗口；方向以内容滚动语义为准，发现反向时只调整方向映射，不破坏单步规则。
