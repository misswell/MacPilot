## 开始前

1. 使用完整打包、具有项目固定签名身份的 MacPilot；单独的 `swift run` 或 ad-hoc 调试程序不能代替恢复助手的签名验证。
2. 在首页打开「屏幕控制」，点击「准备恢复助手」。如果系统要求批准，打开「后台项目设置」允许助手运行，再刷新。
3. 确认界面显示「恢复助手与紧急快捷键已就绪」。如未就绪，不继续测试屏幕停用。
4. 准备 Mac 本地键盘。`⌃⌥⌘9` 是固定解除控制快捷键；其他 MacPilot 功能不能使用该组合。
5. 保存正在编辑的工作。真实屏幕操作须由用户明确授权；可隔离的 AgentSpace 会话可用时使用它。记录系统版本、Mac/GPU、显示器和转接器、UU 版本、分辨率及镜像状态。

恢复终端入口（仅在需要解除控制时由用户执行）：

```sh
/Applications/MacPilot.app/Contents/MacOS/MacPilotDisplayRecovery --restore
```

该命令与助手通信，不会另建控制服务或开放网络端口。必须检查退出状态及实际屏幕；请求已送达不等于屏幕已恢复。

## 实体屏控制

- 单实体屏：停用按钮不可用；绕过 UI 的模拟测试也必须被安全核心拒绝。
- 两个独立实体屏：停用一个，另一个保持可用；原屏不再承载桌面。分别核对内屏、外接屏。
- 选定一屏「仅保留」：该屏成为主屏，Dock 和可操作窗口可达；在确认窗保留配置。
- 不确认保留：倒计时结束后恢复实体屏、原主屏及排列，记录实际恢复耗时。
- 菜单「解除屏幕控制」与本地 `⌃⌥⌘9` 都可用；在首页关闭功能后，菜单恢复入口仍保留。
- 目标拔出、合盖或镜像状态改变时，不能继续停用剩余唯一输出。对断开的屏幕保留待恢复记录，不虚报全部恢复完成。

显示器停用不等于硬件断电；部分显示器可能仍保持背光或指示灯。按实际状态记录，不以日志里的配置成功判断物理熄屏。

## UU 自动策略

- 默认「不调整屏幕」时，打开/连接 UU 不改变显示器。
- 在辅助功能权限不足、UU 主窗口不可读取、控制端不明确或多个控制端连接时，不进行新的自动关屏。
- 第一次启动 MacPilot 时已经存在的 UU 连接，需点击「应用当前 UU 策略」；确认断开后的新连接才自动应用，避免恢复后立即重新关屏。
- 仅保留实体屏：选择固定实体屏，确认后持续工作；UU 断开或无法确认连接时恢复其他实体屏。
- 手动解除后，同一次 UU 连接不得再次自动关闭屏幕；「应用当前 UU 策略」可由用户显式重新启用。
- 修改规则或分辨率先恢复，随后由用户重新应用或等待新连接。缺失的目标不能被任意替换。

## 虚拟屏

- 先选「增加虚拟屏，保留实体屏」，填写偶数物理像素尺寸；核对 HiDPI 的逻辑尺寸和 60 Hz。
- 在 UU 显示面板手动选择「MacPilot Remote Display」；画面确认窗口必须位于虚拟屏。
- 未确认虚拟屏时，实体屏始终开启；超时或创建失败不能进入停用实体屏阶段。
- 「创建虚拟屏并关闭实体屏」须先在虚拟屏确认可见、可操作，然后进入第二次保留布局倒计时；未确认则恢复。
- UU 断开、手动解除、退出 MacPilot 时，先核验实体屏可用，再移除虚拟屏。实体屏恢复失败时保留唯一可用虚拟输出。
- 连续修改尺寸、快速连接/断开、快速反复确认/解除时，无并发重配置、迟到关闭或快速销毁尚未稳定的虚拟屏。
- 记录远程实际画面，不把对象创建成功、online 数量或屏幕录制成功单独作为 UU 可操作的证明。

## 异常恢复与既有功能

- 模拟驱动验证：主程序失联、本地确认超时、远程租约失效、助手重启、写盘失败、配置错误、旧代次、部分恢复失败、数字 ID 重用。
- 经单独授权后，在隔离会话验证主程序崩溃、助手正常退出/异常退出、睡眠唤醒及用户会话切换。不能把模拟通过当作真实恢复证据。
- 活跃控制时，MacPilot 的全屏遮黑和亮度归零不得隐藏唯一输出；正常系统睡眠和 Awake 的既有策略不应被新增断言改变。
- 截图、录屏、贴图、BLE 和原有关闭屏幕行为按实际涉及的路径回归；不要在自动化测试中真实锁屏或发送登录按键。
- 普通退出应等待恢复；不能确认恢复时取消退出并保留助手。版本更新的强制退出兜底也不得跳过恢复屏障。
- 更新/降级或移动 App 后核对助手注册、签名、恢复日志与菜单入口。未完成日志不能随普通配置回滚被覆盖。

每次填写：步骤、期望、实际画面、恢复触发入口、恢复耗时、残留 journal、失败代码及是否需要人工介入。私有显示接口和系统显示服务可能失败；即使本清单通过，也不承诺系统崩溃、显示器断电等情况下始终有可见画面。
