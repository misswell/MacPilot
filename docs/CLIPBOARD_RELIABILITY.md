# 剪贴板历史与详情可靠性

## 2026-10-10 排查

用户设置为 1000 条，但观察到仅 107 条。只读检查时文件有 108 条、无固定条目，最早复制时间为 2026-10-09 14:12（北京时间）。这不是对用户复制次数的完整审计。

真实加载回路发现：`ClipboardModel.history` 先创建默认上限为 100 的 `ClipboardHistory`，构造时立即加载并裁剪，随后才赋用户的 1000 上限。隔离 fixture 中，150 条在这条旧调用链中变为 100 条；后设 1000 无法恢复已删除内容。修复后构造时传入已加载设置，通过 Model 首次加载、flush 和重载验证不会截断到 100。

另有未在设置中展示的 30 天淘汰规则，启动和小时维护都执行。旧年龄契约能复现未达到数量/容量上限的记录被删除。现在取消按年龄自动过期，仍保留数量上限、重复内容合并及 2 GiB 容量保护，并在中英文设置中说明。

修复不能凭空恢复已经淘汰的旧记录。排查和测试没有修改用户的真实历史文件或内容目录。

## 详情展开与收起

保留悬停一秒展开和 0.15 秒离行宽限，去掉 AppKit 窗口尺寸动画和 SwiftUI 隐式动画。收起不再等待另一个 0.25 秒计时。详情直接展开/收起，面板左缘、纵向位置和高度保持不变；空间不足时限制右侧扩展宽度，不移动列表。

自动回归验证状态机和纯几何；它不替代用户桌面上的最终视觉验收。

## 副屏智能识别单击

用户进一步说明：智能识别边框后单击，副屏没有确认选区框和控制点；拖动框选正常，两个复制入口都遇到过。

按真实控制器的“悬停识别 → 单击 → 选区预览 → 复制回调”回路复现：识别器返回全屏坐标，但单击分支将其直接交给要求视图局部坐标的代理，窗口再转换一次。副屏横向原点为 1920 时，正确的 `(2200, 230, 240, 160)` 变为 `(4120, 230, 240, 160)`，选区离开屏幕，边框隐藏、控制点为零。主屏原点为零，掩盖了重复偏移；拖动分支不经过这处错误。

单击提交前先把识别框转换为视图局部坐标，保持代理契约；识别点也通过 AppKit 的视图/窗口转换获得全屏坐标，不再手工加窗口原点，以覆盖内容区偏移。

- 当前 `FrozenAreaCaptureSession` 的负坐标、竖屏、混合 1×/2× 裁图覆盖通过。
- 注入隐藏呈现/光标效果，真实 `SnapzyAreaSelectionController` 的副屏手动/智能拖动链以及主/副屏智能单击链验证显示器、选区框、八个控制点、工具栏及复制回调。旧代码副屏单击失败，修复后六项通过，包括主/副屏内容区纵向偏移 28 点的场景。
- 上述测试直接调用视图事件处理器，不覆盖 WindowServer 对真实鼠标事件的命中和路由。当前后台会话能枚举显示器，但活动显示器列表为空，AgentSpace 不可用，未在用户会话显示测试窗口。

该回路已复现与用户描述一致的确定性坐标错误，但不替代升级后的真实桌面视觉验收。不要求用户录屏；不自动重启应用/系统组件，不重置权限，不改写配对或用户数据。

剪贴板和选区回归已加入主分支 CI 筛选。仅有一台显示器的 CI 会跳过依赖副屏的用例；本地验证实际枚举到两台显示器并执行了全部六项。截图 PNG 测试使用独立命名的 pasteboard 和临时缓存 URL，不再写入用户的共享截图缓存。
